# 政企项目材料标准化与智能生成平台数据库设计文档

文档版本：V1.0  
数据库：MySQL 8  
数据库名称：`gems_platform`  
字符集：`utf8mb4`

## 1. 设计原则

- 系统表使用 `sys_`，工作流表使用 `wf_`，代码生成表使用 `gen_`，业务表使用 `biz_` 前缀。
- 主键采用数据库自增或业务既有策略；关联字段建立必要索引。
- 金额和比例使用定点数保存，不使用浮点数承担最终财务精度。
- PPT、附件等大文件保存在文件系统，数据库保存元数据和相对路径。
- 删除业务数据前检查模板默认状态和项目关联关系。

## 2. 核心表

| 表名 | 用途 |
|---|---|
| `sys_user` | 用户账户 |
| `sys_role` | 角色信息 |
| `sys_menu` | 菜单与权限标识 |
| `sys_dept` | 部门组织树 |
| `sys_post` | 岗位信息 |
| `sys_user_role` | 用户角色关系 |
| `sys_role_menu` | 角色菜单关系 |
| `sys_dict_type`、`sys_dict_data` | 数据字典 |
| `sys_config` | 系统参数 |
| `sys_oper_log`、`sys_login_log` | 操作与登录审计 |
| `biz_selection_project` | 甄选结果项目主表 |
| `biz_selection_bidder` | 投标方明细 |
| `biz_selection_ppt_template` | 甄选PPT模板元数据 |
| `biz_initiation_project` | 立项项目主表及业务JSON数据 |
| `biz_initiation_finance_item` | 立项财务明细 |
| `biz_initiation_attachment` | 立项附件元数据 |
| `biz_initiation_ppt_template` | 立项PPT模板元数据 |
| `wf_business`、`wf_model_meta`、`wf_approval_record` | 工作流业务关联与审批记录 |
| `gen_table`、`gen_table_column` | 代码生成元数据 |

## 3. 主要关系

- 用户与角色：`sys_user` ↔ `sys_user_role` ↔ `sys_role`。
- 角色与菜单：`sys_role` ↔ `sys_role_menu` ↔ `sys_menu`。
- 甄选项目与投标方：`biz_selection_project` 一对多 `biz_selection_bidder`。
- 立项项目与财务项：`biz_initiation_project` 一对多 `biz_initiation_finance_item`。
- 立项项目与附件：`biz_initiation_project` 一对多 `biz_initiation_attachment`。

## 4. 财务数据约束

- 金额单位统一为万元，展示精度通常为两位小数，内部计算保留原始精度。
- 税率以百分比或约定小数形式存储时，前后端必须使用同一换算约定。
- 合同金额、增值税、不含税金额、净利润率等派生值应由统一公式生成。
- 收益测算输入、公式结果和PPT嵌入工作簿必须来源一致。
- 用户可恢复的默认值由对应标准收支测算表重新汇总，不使用固定常量。

## 5. 初始化顺序

```bash
mysql -h 127.0.0.1 -P 13316 -u gems_app -p gems_platform < scaffold_base_init.sql
mysql -h 127.0.0.1 -P 13316 -u gems_app -p gems_platform < selection_module.sql
mysql -h 127.0.0.1 -P 13316 -u gems_app -p gems_platform < initiation_module.sql
```

脚本位置为 `scaffold-system/sql/`。首次部署前应在测试库执行并核对，生产变更必须使用单独增量脚本，不重复执行破坏性初始化。

## 6. 备份恢复

```bash
mysqldump -h 127.0.0.1 -P 13316 -u gems_app -p \
  --single-transaction --routines --triggers gems_platform > gems_platform.sql
```

数据库备份必须与 `/home/glory/gems-platform/data` 文件备份保持同一时间点，恢复后抽查模板、附件路径与项目记录的一致性。
# V1.1 外部协作扩展

- `sys_user` 新增 `real_name`、`audit_status`、`audit_remark`、`audit_by`、`audit_time`，并为手机号建立唯一索引。
- 新增内置角色 `external_user`，数据范围为 `SELF`。
- 新增 `user_document` 表，保存文件元数据、提交人/部门、点评状态、反馈、审核人与时间；物理文件由 `scaffold.documents.storage-path` 指定目录保存。
- 数据库扩展脚本为 `scaffold-system/sql/user_document_module.sql`。
- `CollaborationSchemaMigration` 会在服务启动时自动补齐缺失字段、文档表、角色菜单和德州市/区县组织数据，用于避免漏执行升级脚本导致注册 500。
