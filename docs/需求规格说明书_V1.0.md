# 政企项目材料标准化与智能生成平台需求规格说明书

文档版本：V1.1
基线日期：2026-09-18

## 1. 建设目标

面向政企项目材料编制场景，统一项目数据、模板、测算口径和文档输出流程，降低重复录入及人工套版成本，提高材料一致性、可追溯性与交付效率。

## 2. 用户身份与权限边界

系统采用统一用户体系，不区分内部用户和外部用户，不再向普通用户分配项目管理员、审核人员、模板管理员等可叠加业务角色。用户仅具有以下三种互斥身份：

| 身份 | 主要职责与权限 |
|---|---|
| 超级管理员 | 拥有管理员的全部权限；设置、取消、禁用及维护管理员和其他超级管理员；处理符合条件的误建账号 |
| 管理员 | 使用全部业务功能，查看和审核全平台业务数据；管理所有普通用户，但不能操作超级管理员或其他管理员 |
| 普通用户 | 创建、编辑和提交本人项目及文档，查看本人提交记录、审核状态和反馈；不得审核、维护模板、查看他人数据或进入系统管理功能 |

身份及权限遵循以下强制规则：

- 管理员和超级管理员的业务权限均不受所属市县限制。
- 管理员只能管理普通用户；可以查看其他管理员，但不得编辑、禁用、删除、重置其密码或变更其身份。
- 只有超级管理员可以提升、取消、维护管理员身份，以及设置其他超级管理员。
- 超级管理员不得禁用或降级自己；系统必须始终保留至少一个启用状态的超级管理员。
- 系统管理权限由用户身份决定，不得通过角色配置或接口参数授予普通用户。
- 权限限制必须同时作用于菜单、前端路由和后端接口；隐藏菜单不得作为唯一权限控制手段。

## 3. 功能需求

### 3.1 用户与权限

- 所有用户统一使用中国大陆手机号登录，手机号全局唯一，原用户名不再作为登录凭证。
- 自主注册填写真实姓名、手机号、所属市县、密码及图形验证码；注册成功后身份为普通用户且立即启用，无需人工审核。
- 本期不接入短信验证码；手机号真实性由用户自行保证，手机号误注册或重复占用由管理员核实处理。
- 后台新增用户的初始密码以及密码重置结果统一为 `123456789`。首次登录或密码重置后的下一次登录必须先修改密码，修改成功前不得访问其他功能。
- 不提供手机号自助找回密码。普通用户联系管理员重置，管理员联系超级管理员重置，超级管理员由其他超级管理员重置。
- 普通用户可以修改姓名、头像和登录密码；所属市县仅可查看；手机号和所属市县只能由管理员修改。
- 修改手机号时必须校验新手机号未被占用；修改成功后旧手机号立即失效。
- 未登录用户不得访问业务接口；无权限操作统一返回明确的无权限结果。

#### 3.1.1 用户管理

- 只有管理员和超级管理员可以进入用户管理；普通用户不得通过菜单、地址或直接调用接口访问。
- 用户列表展示姓名、手机号、身份、所属市县、账号状态、首次登录待改密状态、注册来源、注册时间和最后登录时间。
- 支持按姓名或手机号、身份、所属市县、启用状态和注册时间查询；手机号在列表默认脱敏，有管理权限的用户可按需查看完整号码。
- 管理员可以新增、查看、编辑、启用、禁用和重置普通用户密码，不得对管理员和超级管理员执行上述操作。
- 超级管理员可以设置或取消管理员、设置其他超级管理员，并维护管理员账号。
- 支持批量启用、批量禁用和批量重置符合当前操作者权限范围的普通用户。
- 支持通过 Excel 批量导入用户，并按当前筛选条件导出用户。导入时必须校验手机号格式、手机号唯一性、必填字段及身份合法性，并逐行返回失败原因。
- 禁用用户后禁止其登录，但保留其历史项目、文档、审批和操作记录；禁用账号可以重新启用。
- 已登录用户被禁用后，其现有会话必须失效。
- 原则上不物理删除账号。只有超级管理员可以删除从未登录且没有任何业务数据的误建普通用户；管理员和超级管理员账号不得删除。
- 启用、禁用、密码重置、手机号变更、所属市县变更、身份变更及删除均属于敏感操作，执行前二次确认并记录审计日志。

### 3.2 甄选结果

- 支持项目新增、查询、修改、删除和分页检索。
- 支持投标方及评审数据维护、评审材料上传下载。
- 支持根据默认或指定模板生成PPT。
- 支持模板上传、下载、设默认、删除；默认模板不得删除。

### 3.3 项目立项

- 支持项目基础信息、项目情况、建设方案、投资计划和附件管理。
- 支持选择收益分析模式，未选择的模式不生成对应页面。
- 支持招投标项目对比及相关数据联动。
- 支持导出前数据完整性和模板兼容性校验。

### 3.4 标准收支测算

- 表格按项目收入、投资、成本分类展示并合并分类单元格。
- 固定项目不可修改且保持白色背景；可编辑项目通过控件能力表达，不依赖强制底色。
- 税率和折旧年限依据模板口径设置，固定项不得被误改。
- 各收益模式分别维护自己的标准收支测算表。

### 3.5 经济效益测算

- 每个收益模式均配套标准收支表和经济效益测算表。
- 默认收入、投资和成本取自紧邻的对应标准收支表，不使用历史常量。
- 用户误删默认值后可一键恢复。
- 支持利润、净利润、净利润率、现金流、IRR、净现值率、静态和动态回收期计算。
- 计算结果、PPT展示和嵌入Excel模板保持同一口径。

### 3.6 文档生成

- 支持根据项目数据和模板生成PPTX。
- 保持模板字体、字号、表格合并、边框、颜色和版式。
- 明细超出模板容量时按既定规则扩展或分页，不遮挡其他内容。
- 生成文件可下载，生成失败给出可定位的信息。

### 3.7 提交与审核

- 项目填报和文档提交统一采用“草稿 → 待审核 → 审核通过 / 退回修改 → 再次提交”的状态流程。
- 普通用户只能查看、编辑和删除本人的草稿，只能查看本人的提交记录、审核状态和反馈。
- 普通用户提交后不得继续修改当前版本；管理员可以审核全平台全部待审核记录。
- 管理员可以选择“通过”或“退回修改”；退回时审核意见必填。
- 退回后普通用户可以修改并再次提交；审核通过后业务内容锁定。超级管理员可以撤销错误审核结果，普通管理员不得覆盖其他管理员已经完成的审核结果。
- 每次提交生成独立版本，保存提交人、提交时间、内容版本、审核人、审核时间、审核结论和审核意见；重新提交不得覆盖历史版本。
- 多名管理员同时审核时，以后端首次成功提交的审核结果为准。后续提交必须因版本已变化而失败，并提示该记录已经由其他管理员处理。

### 3.8 站内通知

- 系统提供站内通知和消息中心，展示未读数量，并支持已读、全部已读和历史消息查询。
- 普通用户提交成功后收到“已进入待审核”通知；审核通过或退回时收到结果通知，退回通知必须包含审核原因。
- 管理员收到新的待审核提交提醒。
- 用户启用、禁用、密码重置及其他账号安全事件生成相应站内通知；无法登录期间产生的通知在账号恢复后可查看。
- 本期不发送短信、邮件或微信通知，后续可扩展通知渠道。

## 4. 非功能需求

- 兼容主流Chromium浏览器，推荐分辨率不低于1366×768。
- 业务数据仅授权用户可访问；传输层由生产环境HTTPS保障。
- 后端对所有用户管理、系统管理、数据所有权和审核接口执行身份及数据权限校验，防止越权访问和参数篡改。
- 单文件上传上限按部署配置，当前建议100MB。
- 服务、数据库、模板和附件应具备备份恢复机制。
- 关键写操作、身份变更、账号安全操作、审核操作、导入和导出动作保留操作日志，日志包含操作者、目标对象、操作前后值、时间和结果。
- 密码必须加密存储，任何页面、接口和日志不得返回当前密码或密码散列。

## 5. 验收标准

- 所有账号均可使用唯一手机号登录；自主注册成功后立即以普通用户身份启用。
- 新增或重置后的密码为 `123456789`，用户未完成强制改密前无法进入其他页面或调用其他业务接口。
- 普通用户只可访问本人项目和文档，不得访问他人数据、审核功能、模板维护或任何系统管理页面及接口。
- 管理员可管理所有普通用户和审核全平台业务，但无法修改、禁用、删除、重置或变更其他管理员和超级管理员。
- 超级管理员可任免管理员；系统拒绝禁用或降级当前唯一启用的超级管理员。
- 已禁用用户无法新建会话，已有会话立即失效，历史业务数据仍能正确关联原用户。
- 同一手机号不能重复注册或导入；批量导入失败时可定位到具体行及失败原因。
- 多名管理员同时审核同一版本时仅允许首个结果成功，后续结果不会覆盖；重新提交后历史审核版本可追溯。
- 用户能够在消息中心收到提交、审核、退回和账号安全通知，未读数量准确。
- 甄选和立项项目可完整保存、再次打开且数据不丢失。
- 输入模板样例数据后，系统测算结果与模板公式一致。
- 所选模式生成对应收益页及附表，未选模式不生成。
- 输出PPT可正常打开，版式无明显错位，嵌入工作簿可打开。
- 服务器重启后服务自动恢复，历史模板和附件仍可访问。

## 6. 统一用户体系迁移要求

- 合并现有系统用户和注册用户数据，不再保留“内部用户/外部用户”分类及两套管理入口。
- 迁移前校验手机号为空、格式错误和重复占用的数据，并形成待处理清单；不得静默覆盖或自动合并无法确认归属的账号。
- 原超级管理员账号在迁移时必须补充唯一手机号；迁移完成后至少保留一个可登录的超级管理员。
- 原注册用户统一迁移为普通用户；原管理员按确认后的身份迁移为管理员。
- 原有项目、文档、审核记录和操作日志重新关联统一用户主键，迁移后所有权和历史操作者信息不得丢失。
- 原“注册用户”管理入口下线，统一通过“用户管理”完成查询及维护。
