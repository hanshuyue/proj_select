# Spring Boot + Vue 后台管理脚手架 PRD

## 1. 产品概述

### 1.1 产品名称

Spring Boot + Vue 后台管理脚手架。

### 1.2 产品目标

提供一套可复用的企业后台管理系统基础平台，使开发团队能够快速创建具备登录认证、权限管理、数据权限、系统管理、代码生成和工作流审批能力的新项目。

### 1.3 产品范围

本 PRD 覆盖第一阶段到第三阶段的核心产品能力：

- 后台管理基础框架。
- RBAC + 数据权限。
- 系统基础管理模块。
- 前端后台布局和组件封装。
- 代码生成。
- 基于 Flowable 的工作流基础能力。

### 1.4 不在当前范围

- 多租户 SaaS。
- 移动端 App。
- 微服务架构。
- 完整低代码平台。
- 复杂动态表单设计器。
- 工作流仿真和灰度发布。

## 2. 用户角色

| 用户角色 | 说明 | 主要诉求 |
| --- | --- | --- |
| 超级管理员 | 系统最高权限用户 | 管理用户、角色、菜单、部门、流程和系统配置 |
| 系统管理员 | 负责系统日常配置 | 维护用户、角色、字典、日志和流程定义 |
| 业务管理员 | 负责业务模块配置 | 使用代码生成、维护业务数据、发起或管理审批 |
| 普通用户 | 后台系统使用人员 | 查看授权菜单、处理待办任务、查看个人已办 |
| 开发人员 | 脚手架使用者 | 基于脚手架快速创建新模块和新项目 |

## 3. 核心业务流程

### 3.1 登录和权限加载流程

1. 用户输入账号、密码和验证码。
2. 后端校验用户身份。
3. 登录成功后返回访问令牌。
4. 前端保存令牌并请求当前用户信息。
5. 前端请求当前用户菜单、路由和按钮权限。
6. 前端生成动态路由并渲染后台布局。
7. 用户访问页面或点击按钮时，前端按权限显示，后端按权限校验。

### 3.2 权限配置流程

1. 管理员创建菜单和按钮权限。
2. 管理员创建角色。
3. 管理员为角色分配菜单和按钮权限。
4. 管理员为角色配置数据权限。
5. 管理员为用户分配角色。
6. 用户重新登录或刷新权限后获得对应菜单、按钮和数据范围。

### 3.3 数据权限生效流程

1. 用户访问需要数据权限控制的业务列表。
2. 后端识别当前用户角色和数据权限范围。
3. 后端根据数据权限追加查询条件。
4. 系统只返回用户有权查看的数据。

### 3.4 工作流审批流程

1. 管理员创建并部署流程定义。
2. 业务用户在业务单据页面发起流程。
3. Flowable 创建流程实例和审批任务。
4. 审批人进入我的待办查看任务。
5. 审批人执行通过、驳回、退回或撤回等操作。
6. 系统记录审批意见和流转轨迹。
7. 流程结束后回写业务单据状态。

## 4. 功能需求

### 4.1 登录认证

#### 功能说明

提供后台管理系统登录、退出、获取当前用户信息和权限信息能力。

#### 功能点

- 账号密码登录。
- 验证码校验。
- 登录成功返回 token。
- 获取当前用户信息。
- 获取当前用户菜单路由。
- 获取当前用户按钮权限。
- 退出登录。
- 登录失败记录。

#### 关键字段

| 字段 | 中文说明 |
| --- | --- |
| username | 登录账号 |
| password | 登录密码 |
| captcha | 验证码 |
| token | 访问令牌 |
| permissions | 按钮和接口权限标识集合 |
| roles | 当前用户角色编码集合 |

#### 验收标准

- 用户输入正确账号密码后可登录系统。
- 用户登录后只能看到授权菜单。
- 未登录访问后台页面时跳转登录页。
- token 失效后接口返回未认证状态，前端跳转登录页。

### 4.2 用户管理

#### 功能说明

管理后台系统用户信息和用户角色关系。

#### 功能点

- 用户列表查询。
- 新增用户。
- 编辑用户。
- 禁用或启用用户。
- 删除用户。
- 重置密码。
- 分配角色。
- 按部门筛选用户。

#### 关键字段

| 字段 | 中文说明 |
| --- | --- |
| userId | 用户 ID |
| username | 登录账号 |
| nickname | 用户昵称 |
| phone | 手机号 |
| email | 邮箱 |
| deptId | 所属部门 ID |
| status | 用户状态 |
| roleIds | 用户关联角色 ID 集合 |

#### 验收标准

- 管理员可按账号、昵称、部门、状态查询用户。
- 新增用户后可登录系统。
- 禁用用户不能登录。
- 用户分配角色后，权限按角色生效。

### 4.3 角色管理

#### 功能说明

维护角色基础信息、菜单权限、按钮权限和数据权限。

#### 功能点

- 角色列表查询。
- 新增角色。
- 编辑角色。
- 删除角色。
- 分配菜单权限。
- 分配按钮权限。
- 配置数据权限范围。
- 配置自定义部门数据权限。

#### 关键字段

| 字段 | 中文说明 |
| --- | --- |
| roleId | 角色 ID |
| roleName | 角色名称 |
| roleCode | 角色编码 |
| menuIds | 角色拥有的菜单和按钮 ID 集合 |
| dataScope | 数据权限范围 |
| deptIds | 自定义数据权限部门 ID 集合 |
| status | 角色状态 |

#### 验收标准

- 角色授权菜单后，用户登录可看到对应菜单。
- 角色授权按钮后，用户可看到对应操作按钮。
- 配置数据权限后，业务列表按权限过滤。

## 6. 非功能需求

### 6.1 性能

- 常规列表接口应支持分页查询。
- 字典、菜单、权限等低频变更数据可缓存。
- 登录和权限加载接口应避免返回无关冗余数据。

### 6.2 可维护性

- 前后端模块边界清晰。
- 统一命名、统一响应、统一异常。
- 权限、数据权限、日志应通过注解或统一拦截方式实现。
- 工作流模块保持可插拔，避免和系统基础模块强耦合。

### 6.3 安全性

- 密码加密存储。
- 接口必须后端鉴权。
- 敏感操作记录日志。
- 文件上传限制大小和类型。
- 防重复提交和基础 XSS 防护。

### 6.4 易用性

- 后台布局清晰，菜单层级不宜过深。
- 表格默认提供查询、重置、分页。
- 表单默认提供校验和明确错误提示。
- 工作流审批页应同时展示业务信息、流程图、审批记录和操作区。

## 7. MVP 验收标准

MVP 完成后应满足：

- 系统可正常启动和登录。
- 管理员可维护用户、角色、菜单和部门。
- 用户权限变更后菜单、按钮和接口权限正确生效。
- 数据权限可对至少一个示例业务表生效。
- 字典可被前端下拉组件复用。
- 操作日志和登录日志可查询。
- 所有后台列表表格提供导出能力。
- 代码生成可生成一个单表 CRUD 模块。
- Flowable 可部署流程、发起流程、处理待办、查看已办和流程记录。
- 前端页面基于 Vue 3、Vite、TypeScript、Element Plus 实现。

## 8. 风险与约束

| 风险 | 影响 | 处理建议 |
| --- | --- | --- |
| 工作流范围过大 | 影响 MVP 交付 | 第一版只做基础审批能力 |
| 数据权限规则复杂 | 查询实现和性能受影响 | 先支持标准部门数据权限 |
| 完全自研组件库成本高 | 前端开发周期变长 | 第一阶段基于 Element Plus 二次封装 |
| 代码生成过度复杂 | 维护成本增加 | 先支持单表 CRUD |
| 多角色数据权限合并规则不明确 | 可能出现越权或权限不足 | 开发前确认最大范围或交集策略 |
