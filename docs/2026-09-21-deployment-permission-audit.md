## 版本差异的已确认原因

代码中开发环境会运行 `CollaborationSchemaMigration` 和 `SelectionSchemaMigration`，生产环境明确禁止自动迁移。原生产 SQL 未完整包含员工 PPT 授权、注册组织目录及旧版甄选表字段。因此只替换 JAR 和前端文件不能使数据库功能一致。这是本地代码已确认的差异，尚未登录云服务器核实当前运行版本。

生产升级步骤见 `deploy/README.md`、`deploy/DATABASE.md`。必须使用同一发布包执行数据库 upgrade，再安装前后端。真实生产数据库地址、口令及持久化路径仍保存在服务器环境文件中。

新增源文件摘要和安装元数据，用于识别含未提交改动的发布版本；安装后同时核对 `app/source-manifest.json` 和实际 JAR、静态文件摘要。

## 角色约定

| 身份 | 角色编码 | 能力 |
| --- | --- | --- |
| 普通员工 | external_user | 注册即启用；甄选、立项填报与 PPT 生成；本人材料提交、查看审核意见、修改后重提 |
| 管理员／采购专员 | biz_admin | 同时保留普通员工角色，兼具材料审批和本人 PPT 制作提交能力 |
| 超级管理员 | super_admin | 系统管理及采购专员身份设置 |

兼容仍在使用的 sys_admin 角色。普通员工及采购专员不能自行提升为管理员。主动停用的账号和角色不会因为常规启动迁移重新启用。

## 已修复的问题

- 菜单和权限查询忽略角色停用、删除状态；禁用账号权限解析未明确拒绝。
- 采购专员赋权未确保基础员工角色存在，目标角色缺失仍可能显示设置成功。
- 开发环境每次启动重新启用已禁用的注册账号。
- 开发环境启动迁移删除既有组织和岗位关系、覆盖管理员姓名，与生产环境规则不一致。
- 员工可猜测项目或附件 ID 访问他人材料；现对甄选、立项的列表、详情、修改、删除、附件及导出入口校验项目归属。
- 前端员工缺少 PPT 提交记录入口，管理员身份阻止本人材料重新提交。
- 前后端用户 ID 字段不一致，退出切换账号后残留动态管理路由，初次访问和权限初始化存在放行窗口。
- 验证码请求失败时前端展示随机伪验证码，无法用于实际登录。
- 工作台向普通员工返回其他人的审批标题及登录活动；现在按对应权限返回全局或本人明细。
